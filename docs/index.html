Superretometer

A plausible answer is not the same as a grounded answer.

Superretometer is a cognitive harness that makes reasoning visible, traceable, and testable — so you can ask: what does this conclusion depend on, and what makes those dependencies real?

A check that cannot fail is not evidence.

The Problem

An AI system or engineering simulation can produce a result that looks correct. The numbers close. The chain of reasoning appears sound. Yet the conclusion rests on premises that have no independent grounding in the physical world.

Consider a reasoning chain from an engineering model:

design decision → geometry → inductance → current → flux → torque → equilibrium → RPM

The chain can be structurally valid and still not be independently grounded. Superretometer makes that distinction explicit, structural, and computable.

Worked Example: Desired RPM, Blocked Warrant

Utility first. Here is the pattern Superretometer is built for — claim → missing grounding → required action.

Claim

A simulation reports that a machine reaches the desired operating speed (RPM). Energy balance closes. Several checks pass. The result looks ready to carry a design decision.

What the graph finds

  • Material properties — manufacturer datasheet
  • Geometry — CAD model or physical measurement
  • Design target — documented human decision
  • Energy balance — conservation law
  • A magnetic parameter calibrated to produce the desired field / RPM — not independently grounded

The dependency that blocks warrant is explicit: a fitted parameter whose training target is the same conclusion the model is asked to justify (CALIBRATED_TO_CONCLUSION).

Why the warrant is blocked

Hitting the desired RPM is not the same as independently predicting it. If a free parameter was tuned until the simulation matched the target, the match is not independent evidence. Plausible is not grounded. A check that cannot fail is not evidence.

Required action

Register an independent measurement or test dataset for that parameter (or remove the claim from design-bearing status until one exists). Then re-run warrant analysis. The four decision gates below stay closed until the missing grounding is present.

From Result to Design Warrant

A simulation result is a file on disk. It is not a conclusion. The four-gate SimulationGatePolicy determines whether a simulation-backed claim may carry a design decision.

Provenance  →  Scope  →  Reality  →  Falsifiability  →  Design-bearing
  • Can we reproduce it? — Complete chain from result artifact to source commit (N-PROV)
  • Does the model represent what the claim is about? — Explicit scope as warrant boundary (N-SCOPE)
  • Are the quantities carrying the claim independently grounded? — Truth-category-appropriate grounding (N-REALITY)
  • Can the checks actually prove us wrong? — Invariants valid for the declared system boundary (N-INVARIANT)

All four gates must PASS for design-bearing. One BLOCK means informative only — not that the simulation failed, but that the warrant chain is incomplete.

What This Tool Does — and Does Not Do

Superretometer evaluates documented dependencies and evidence under explicit rules. It inspects the provenance graph you register: what depends on what, which roots are independent, which checks can fail, and which anti-patterns are present.

  • It does not automatically confirm that the physical world matches the model.
  • It does not invent missing measurements or replace laboratory work.
  • Its conclusions depend on correct registration of dependencies — omit a calibration edge and the warrant analysis cannot see it.
  • Warrant is derived state from the current graph, not a permanent certificate of truth.

Architecture (overview)

Superretometer combines generative reasoning with persistent structure and an explicit reality check:

REASON

LLM or engineer forms hypotheses and candidate justification chains.

CONTINUITY

Emergent Memory keeps evidence, decisions, and observations across sessions.

STRUCTURE + TRACE

CAFCR / Lines of Reasoning structure each step: claim, viewpoint, knowledge used.

REALITY CHECK

Inspired by the EPR completeness criterion as an epistemic analogy — not a physics claim.

REASON → TRACE → REALITY CHECK → ACT → MEASURE → UPDATE

Emergent Memory & Emergent Strategy

Emergent Memory provides the persistent graph backbone: knowledge, evidence, decisions, and observations survive across sessions.

Emergent Strategy closes the adaptive loop: act → observe → learn → revise → act again. Developed by Nikolai Fasting and Maciej Kucharz at Emergent Company. Emergent Strategy is grounded in Nikolai's experience building over 30 startups and inspired by Ready, Fire, Aim (Michael Masterson, 2008): bias toward action, learn from outcome, iterate.

Gerrit Müller — CAFCR & Lines of Reasoning

CAFCR expands to Customer Objectives, Application, Functional, Conceptual, Realization. Müller's PhD thesis, CAFCR: A Multi-view Method for Embedded Systems Architecting; Balancing Genericity and Specificity (TU Delft, 2004), introduced structured multi-view architecting and Lines / Threads of Reasoning — tracing decisions from stakeholder need through viewpoints to realization so the reasoning chain can be audited and restarted.

Superretometer's Thread model computationally applies that principle: each thread records claims, viewpoints, and knowledge objects used.

Einstein, Podolsky & Rosen — 1935

Can Quantum-Mechanical Description of Physical Reality Be Considered Complete? (Physical Review, 47, 777, 1935) proposed a criterion of reality and argued that a complete theory must account for every element of physical reality.

Superretometer adapts this as an epistemic analogy for engineering reasoning: a conclusion is warranted only if the quantities and claims carrying it possess independently grounded counterparts outside the model.

This is an analogy, not a claim about quantum mechanics. We do not apply quantum physics to engineering problems. We apply the structural question EPR asked about the relationship between description and reality.
