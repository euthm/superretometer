# Superretometer v0.6.5 — Release Notes

**Date:** 2026-09-06
**Branch:** `release/v0.6.5`
**Status:** Candidate (pre-release)

## Summary

Distribution and packaging repair. Packaged MCP server, new CLI, zero-dependency MCP transport. No Cognitive Harness semantic changes.

## What Changed

### Packaged MCP Server

The MCP server has moved from `transports/mcp/server.py` (repository checkout, excluded from wheel) into the packaged `cognitive_harness/mcp/server.py` (included in wheel).

After `pip install cognitive-harness`, the MCP server is available without any repository checkout or PYTHONPATH manipulation.

**Migration:** `transports.mcp.server` remains as a deprecated compatibility shim that emits `DeprecationWarning` and re-exports from `cognitive_harness.mcp.server`.

### New CLI

`superretometer` is now a proper CLI entrypoint registered via `[project.scripts]`:

```bash
superretometer --version   # 0.6.5
superretometer --help      # usage
superretometer             # shows help (does NOT start MCP server)
superretometer mcp         # starts MCP server on stdin/stdout
```

Bare invocation shows help. It will not silently start a long-running MCP server.

### Zero-Dependency MCP Transport

The `[mcp]` optional dependency (`mcp>=1.0.0`) has been **removed**. The MCP server uses only stdlib JSON-RPC (`json`, `sys`). No external MCP SDK is needed.

The `[mcp]` extra is preserved as empty for pip compatibility:
```bash
pip install "cognitive-harness[mcp]"  # works, installs nothing extra
```

### Version Consistency

Single version source from package metadata:

```python
from cognitive_harness import __version__  # "0.6.5"
```

Verified chain:
```
package metadata  ==  cognitive_harness.__version__  ==  superretometer --version  ==  MCP serverInfo.version
```

Hardcoded `"0.1.0"` in MCP `serverInfo` is eliminated.

## For New Users: What Changed?

- The MCP server is now **included in the package** — no repository checkout needed.
- A proper **CLI** (`superretometer`) replaces manual `python -m transports.mcp.server`.
- **No external MCP SDK dependency** — the transport uses stdlib JSON-RPC.
- Version is **consistent** across package, CLI, and MCP protocol.

## No CH Semantic Changes

Cognitive Harness model, reasoning, warrant, and orchestration semantics remain v0.6.4-compatible. This release is purely distribution, packaging, and public transport repair.

## Validation

- **Python 3.10 / 3.12 / 3.13**: GitHub CI passing
- **Tests**: 82 tests pass (69 original + 13 new MCP transport regression tests)
- **Wheel builds clean**, contents inspected, venv smoke passes

## Known Limitations

- `propose_thread` not available through MCP (no ConsumerAPI backing; use `OrchestrationEngine` directly)
- `open_tensions` uses internal `_tensions` dict (no public tension listing API yet)
- InMemoryStorage `_kos` dict accessed for impact_set/justification_path titles (public `list_all_kos()` used for orientation)
