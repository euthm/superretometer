# Superretometer v0.7.0 — Release Notes

**Date:** 2026-09-06
**Branch:** `implementation-provenance`
**Status:** Candidate (pre-release)

## Summary

ImplementationGatePolicy: a six-gate warrant dimension for code-bearing claims.
An "implemented" claim must now trace to an exact repository + exact code state +
matching validation state. This is a semantic extension, not a packaging change.

## Semantic Difference vs v0.6.5

| Capability | v0.6.5 | v0.7.0 |
|---|---|---|
| Simulation provenance | SimulationGatePolicy (4 gates) | Unchanged |
| Implementation provenance | **None** | **ImplementationGatePolicy (6 gates)** |
| Canonical repo identity | — | `github.com/owner/repo` |
| Worktree reproducibility | — | `worktree_clean` + `worktree_diff_sha256` |
| Test-state binding | — | `tested_commit`, `test_exit_code`, `test_command`, `test_timestamp` |
| Falsifiability gate | Simulation only | Implementation + simulation |
| Dependency integrity | — | `submodule_pins` / `tested_submodule_pins` |

"Implemented" is now treated as an epistemic claim that must trace to:
1. A canonical repository identity
2. An exact commit
3. A reproducibly identified code state (clean commit or dirty + diff hash)
4. Complete test execution evidence bound to that exact state
5. At least one falsifiable validator
6. Consistent dependency/submodule state

## What Changed

### Added: ImplementationProvenance Dataclass

New dataclass in `cognitive_harness.model.ko` with 21 fields:
- Repository identity: `repo_remote_sanitized`, `repo_remote_canonical`, `commit`, `branch`
- Worktree state: `worktree_clean`, `worktree_diff_sha256`
- Dependencies: `submodule_pins`, `tested_submodule_pins`
- Test execution: `test_run_id`, `validator_ko_id`, `test_command`, `test_exit_code`,
  `test_result_sha256`, `tested_commit`, `tested_worktree_diff_sha256`, `test_timestamp`
- Session linkage: `session_id`, `epf_ready_id`

### Added: ImplementationGatePolicy

Six-gate policy in `cognitive_harness.analysis.implementation_gate_policy`:

| Gate | Rule | PASS Condition |
|---|---|---|
| Provenance | N-IMPL-PROV | Canonical remote + commit present |
| Scope | N-IMPL-SCOPE | Canonical remote matches scope-declared remote |
| Worktree | N-IMPL-WORKTREE | Clean worktree (commit alone represents state) |
| Test | N-IMPL-TEST | Complete evidence chain + exit 0 + commit match + TZ timestamp |
| Falsifiability | N-IMPL-FALSIFY | ≥1 validator with non-empty `what_would_falsify` |
| Dependency | N-IMPL-DEPENDENCY | Submodule pins match between claim and tested state |

All six gates must PASS for `design_bearing = true`.

### Added: Canonical Remote Normalization

`canonical_remote(remote) → hostname/owner/repo`

Normalizes transport syntax (git@, https://, ssh://, git://), SSH ports, and
credential stripping. Lowercase hostname. Generic host support (GitLab, self-hosted).

### Added: Test Identity Separation

Three distinct identities:
- `test_run_id` — external runner/execution ID (not a CH graph reference)
- `validator_ko_id` — CH KnowledgeObject containing validation evidence
- `test_result_sha256` — immutable test output artifact hash

### Added: Schema

`spec/schemas/provenance.schema.json` extended with `implementation_provenance`
definition covering all 21 fields with proper types and patterns.

### Added: Conformance Tests

30 normative CH-IMPL conformance tests (CH-IMPL-001 through CH-IMPL-030) covering:
- Identity normalization (6 tests)
- Worktree reproducibility (3 tests)
- Test binding (10 tests)
- Falsifiability (3 tests)
- Dependency integrity (5 tests)
- Timestamp semantics (3 tests)

Total: 50 implementation tests, 136 total conformance tests.

## User-Visible Effect

- Claims about "implemented" code now require six-gate validation
- Legacy partial test provenance (test_run_id + test_result_sha256) → UNKNOWN, not PASS
- Timezone-aware ISO 8601 timestamps required for complete validation provenance
- Credentials in remote URLs are stripped before storage

## Migration/Compatibility

- **Backward compatible** with v0.6.5 simulation semantics
- Legacy `repo_remote` field still accepted (auto-normalized)
- `repo_remote_raw` deprecated → `repo_remote_sanitized`
- Old claims with incomplete test evidence → UNKNOWN (not PASS)
- No breaking changes to existing SimulationGatePolicy

## New Guarantees

1. Repository identity is transport-agnostic: `git@`, `https://`, `ssh://` → identical canonical form
2. Branch is context, not identity: detached HEAD + commit is valid
3. Test evidence must be bound to exact tested state (commit + worktree)
4. Credentials are never persisted in provenance records
5. Submodule state must be consistent between claim and tested evidence

## Known Limitations

- **Falsifier applicability (v0.7):** established by membership in `ko.validators` list;
  explicit `FalsifiableValidator.ko_id` cross-link enforcement deferred to v0.8
- **Worktree diff computation:** normative rule defined but not implemented in CH;
  external tool (oc) must supply the hash
- **No package-manager dependency support:** only Git submodules in v0.7
- **No freshness/expiry semantics:** `test_timestamp` is audit metadata only

## Validation Evidence

- 136 total conformance tests (84 implementation + 52 legacy)
- Schema/dataclass field-for-field consistency verified (21 fields)
- All normative rules have spec text + positive test + negative/unknown test
- No tautological tests

## New-User Summary

v0.7.0 adds the ability to make epistemically rigorous claims about implemented code.
If you claim "X is implemented," Superretometer now requires you to prove:
what repository, what commit, what code state, what tests, what would falsify it,
and that all dependencies are in the claimed state.
