# Superretometer v0.7.1 — Release Notes

**Date:** 2026-11-07
**Branch:** `fix/truth-category-and-contradicts`
**Status:** Candidate

## Summary

Fixes four critical issues found by harness test run 9070c892: evidence visibility in warrant analysis, counter-evidence mechanism, truth_category passthrough, and justification_path ID resolution. Adds contradiction detection to warrant analyzer.

## Semantic Difference vs v0.7.0

| Capability | v0.7.0 | v0.7.1 |
|---|---|---|
| Evidence visibility | Broken: `_create_edge` used CH IDs, edges failed silently | Fixed: `_resolve_ch_id` resolves to Memory UUID |
| Counter-evidence | Missing: `CONTRADICTS` unused in submission path | Implemented: `evidence_relation_type` parameter, warrant detects |
| TruthCategory passthrough | Missing: `Proposal` had no `ko_truth_category`, always ASSUMPTION | Implemented: MCP → Proposal → Memory → readback chain |
| TruthCategory validation | None | Rejects invalid values with clear error listing valid options |
| Contradiction detection | Missing in warrant | `contradicting_kos` in WarrantResult, UNWARRANTED when present |
| delete_ko | Missing | Soft-delete via Memory API, clears mappings |

## Changes

### Model (`ko.py`, `proposal.py`)
- `CONTRADICTION_INBOUND = frozenset({CONTRADICTS})` — relation set for contradiction detection
- `CONTRADICTS` added to `IMPACT_RELATIONS`
- `Proposal.ko_truth_category: TruthCategory | None` — explicit truth category for CREATE_KO
- `Proposal.evidence_relation_type: str = "supports"` — relation direction for CREATE_EVIDENCE

### Runtime (`runtime_server.py`)
- Parse `ko_truth_category` from MCP args with `TruthCategory` validation
- Parse `evidence_relation_type` for CREATE_EVIDENCE proposals
- MCP schema documents both new parameters
- Invalid `truth_category` returns clear error: `Invalid truth_category: 'x'. Valid: [...]`

### Storage (`memory_adapter.py`)
- `add_evidence`: respects `relation_type` (supports/contradicts) for edge type
- `add_evidence`: resolves `claim_id` to Memory UUID via `_resolve_ch_id` before creating edge
- `validate_and_execute` CREATE_KO: passes `ko_truth_category` to `KnowledgeObject` when provided
- New `delete_ko` method: soft-delete via Memory API, clears ID mappings

### Warrant (`warrant_analyzer.py`)
- `_find_contradictions()`: detects incoming CONTRADICTS edges
- `WarrantResult.contradicting_kos`: lists contradicting KOs
- Contradictions set warrant to `UNWARRANTED` with `PHYSICALLY_UNREALIZABLE` anti-pattern diagnosis
- Contradictions override all other warrant assessments

### MCP (`server.py`)
- `contradicting_kos` field in warrant response

### Tests
- 24 new regression tests in `test_truth_category_and_contradicts.py`
- All 241 tests pass (24 new + 217 existing)

## Known Limitations

1. **Memory Go search fix not included**: `service.go:2918` missing `supersedes_id IS NULL` filter in `executeSearchEntities`. Tracked separately in `emergent.memory`.
2. **No `delete_edge` in MemoryAdapter**: Cannot remove edges after creation.
3. **`scan_anti_patterns` blocked**: `enumeration_complete=False` in MemoryAdapter (design decision).
4. **`conditionally_warranted` for HYPOTHESIS**: Default `truth_category=ASSUMPTION` causes conditional warrant even without evidence. This is existing behavior.
